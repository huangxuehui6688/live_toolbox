ASR 跟读（字幕）· live_toolbox 技术方案 v1

老板：这一份不是开发，是先把"用哪个 ASR 引擎、跟读和字幕谁先做"这两个核心决策拍板。你看完一句话回我就开干。

一句话定位：ASR 跟读（字幕）= 同一个 ASR 底座（语音→文字）的两个产品场景—— 跟读是给主播提词器用的（"我读到第几行了，稿子滚到第几行"）， 字幕是给观众看的（"主播说了什么，显示成文字"）。 底层是同一个引擎，区别只在输出形态（行号 vs 文字流）。

★ 方案 A（端侧 FunASR）推荐理由（三点）

  • 跟项目既定方向一致：直播项目的技术架构白纸黑字写"端侧零成本为主：FunASR/Whisper ASR"，UI 已经写"FunASR 智能跟读"，换引擎是改方向。
  • 两个场景都最佳：跟读需要的"流式 + 时间戳 + 行号定位"和字幕需要的"流式 + 标点"在 FunASR 都是开箱即用，Whisper 要补、speech_to_text 没有、云端要看 API。
  • 成本结构决定一切：方案 C 云端每分钟烧 token，2 小时直播 ¥0.5，叠加多语言扩展每场几块，长期是黑洞；端侧一次集成零边际成本。

方案 A 的硬骨头（一次性，不是长期）：Flutter 集成 FunASR 要走 FFI + ONNX 编译，主流路线两条——

  • 路线 1：用阿里达摩院 funasr-runtime C++ SDK + NDK 编译成 .so，Flutter 端写 MethodChannel 调用 → 灵活但工作量大（3-5 天）
  • 路线 2：用 sherpa_onnx Flutter 插件，它已支持 FunASR ONNX 模型（paraformer 流式 + 标点模型）→ 工作量小（1-2 天）

建议走路线 2。sherpa_onnx 是开源 ASR 引擎（k2-fsa 出品），不是 sherpa-ncnn，支持 FunASR 的 paraformer 模型 + 标点模型，Flutter 端用 sherpa_onnx pub 包即可，编译在包里完成。

3 · 实现路径（分两阶段，共用一个 ASR 服务）

第一步 · 搭 ASR 底座（共用）

新增：lib/services/asr_service.dart  ← 唯一的 ASR 接入点，跟读/字幕都调它
├─ start() / stop() / pause() / resume()
├─ stream: Stream<AsrResult>  ← 流式输出：{text, isFinal, startMs, endMs, confidence}
├─ 内置：paraformer 流式模型 + 标点模型
└─ 权限：复用 permission_handler 麦克风权限

新增：lib/services/asr_aligner.dart  ← 跟读专用
├─ 输入：ASR 流 + 提词稿（按"\n"分行）
├─ 算法：滑动窗口比对 ASR 文本与每行，计算"主播读到了第几行"
└─ 输出：Stream<int>  当前行号

这一步不接任何 UI，只把 AsrService 跑通，模拟一段录音能流式出文字就算成。

第二步 · 提词器接真 ASR（跟读）

改 teleprompter_page.dart 的 _readBar() 和滚动逻辑：

  • 删 _meter 随机数 / _meterTimer / _spdLabel 假语速条
  • 改 _scroll 匀速定时器为：AsrAligner 推送新行号 → setState 滚动
  • 提词器"AI 跟读"开/关按钮：关 = 退回匀速定时器（旧逻辑保留），开 = 走 ASR
  • "跟读准确率"展示真实数据：AsrResult.confidence 滑动平均

这次能直接出可验证效果——把提词器开到 AI 跟读，对麦克风读稿子，UI 上能看到行号跟着走。

第三步 · 直播间字幕（共用 ASR 底座）

从第二步复用 AsrService，新建字幕层：

  • 新增页面：lib/pages/subtitle_settings_page.dart（字幕样式：字号/位置/底色/单/双语，主页「字幕」入口和直播间「字幕」按钮都跳这里）
  • 新增组件：lib/widgets/live_caption_overlay.dart（叠在相机预览上的字幕条，VirtualBackgroundView 之上用 Stack 叠加）
  • 直播间接入：在 live_room_page.dart 右侧"字幕"按钮 onTap 切 bool _captionOn，开 = 启动 AsrService + 显示 overlay，关 = 停

这一步的关键是"复用第二步的 AsrService"，不重复接入。

阶段时间估算（端侧 FunASR 路线 2 走法）：

  • 第一步 ASR 底座：1-2 天（含 sherpa_onnx 集成 + 模型下载 + 流式跑通）
  • 第二步 提词器跟读：半天-1 天（把假数据替换为真流）
  • 第三步 直播间字幕：1 天（页面 + 组件 + 接入）
  • 合计 3-4 天，可分两天提交（先跟读再字幕）

4 · 需要老板拍板的点

三个决策，一句话回我就行：
  • 决策 1 · ASR 引擎：选 A（端侧 FunASR，路线 2 走 sherpa_onnx 插件）/ B（端侧 Whisper）/ C（云端 API）/ D（系统 speech_to_text）？
    我推荐 A 路线 2，理由见上。
  • 决策 2 · 字幕语言范围（仅影响字幕场景）：首版字幕只做中文（与跟读稿语种一致），还是同时支持英/西/葡？
    如果选多语字幕，FunASR/Whisper 对外语支持不如中文，需要换引擎或加翻译层，工程量翻倍。
  • 决策 3 · 顺序：先做"提词器跟读"再做"直播间字幕"（推荐，先验证 ASR 链路），还是两个一起做？
    我推荐分两步：跟读先跑通真 ASR，再复用底座做字幕。
