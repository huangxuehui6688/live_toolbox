# 提词器悬浮窗改造 · 执行任务书

> 项目：`live_toolbox`（AI直播副驾驶，Flutter，Android）
> 目标：**把提词器从"App 内页面"改造成"系统悬浮窗"**，让主播在抖音/快手直播时也能看到台词。
> 本任务书自包含，一个 Agent 可从头做到尾。

---

## 一、为什么改（背景，先读）

现在提词器是 App 内的一个页面，**真直播时没用**——主播开播是在抖音 App 里，根本看不到我们 App 内的提词页。

竞品（绿幕助手）的正解是**悬浮窗提词**：浮在抖音上面，主播边播边看，不用切 App。

**已确认的前提（别再纠结，直接采信）：**
- 真人带货是**摄像头直播**，观众看的是主播的人，**拍不到手机屏幕** → 悬浮窗**不会穿帮**。
- 只有"录屏直播"才会把悬浮窗录进去（我们的数字人走那条路，**数字人不用悬浮窗**）。
- 悬浮窗是 **Android 能力**，iOS 系统不支持 → **本次只做 Android**。

## 二、现有资产（别推翻重做）

智能跟读内核已经做了，有价值，**保留复用**：

| 文件 | 作用 |
|---|---|
| `lib/services/asr_service.dart` | sherpa-onnx 流式语音识别（已改常驻 worker isolate） |
| `lib/services/asr_aligner.dart` | 跨句累计 + 容错对齐，判断主播念到哪一行 |
| `lib/pages/teleprompter_page.dart` | 现有提词 UI（要改成"台词库列表"） |

**本次 = 把已有内核装进"悬浮窗"这个新壳，不是重写。**

## 三、改造步骤（按顺序做）

### 阶段 1：悬浮窗能力

1. 选悬浮窗插件（推荐 `flutter_overlay_window`；若有更合适的可换，但要在报告里说明原因）。
2. `android/app/src/main/AndroidManifest.xml` 加权限：
   ```xml
   <uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />
   ```
3. 新建 `lib/services/overlay_service.dart`，实现下面第五节的接口（`OverlayService` 单例）。
4. 新建 `lib/widgets/teleprompter_overlay.dart`（悬浮窗里的提词 UI）：
   - 大字号（主播一米外看清）、当前行高亮、其余行暗色
   - 可拖动位置、可调透明度（别挡直播画面）
   - 尽量窄小，不抢屏幕
5. 权限申请：首次开启引导授权（国产 ROM 入口不同，提示文案写清楚）。

### 阶段 2：台词库（对齐绿幕助手）

6. 新建 `lib/services/script_store.dart`：支持**多套话术草稿**
   - 新建 / 编辑 / 删除；本地持久化（shared_preferences 或文件）
   - 数据结构见第五节 `Script`；列表按更新时间倒序

### 阶段 3：跟读适配

7. 主播念词时，把 ASR 算出的"当前行"通过 `OverlayService.updateLine(index)` 实时传给悬浮窗刷新高亮。
8. **关键风险**：悬浮窗显示时宿主 App 可能退后台，Android 会限制/掐断后台录音。若发现录音被断，需要 **前台服务（Foreground Service）** 保活——需要时在 AndroidManifest 声明前台服务权限与 Service（本阶段自己处理，统一在阶段1的 Manifest 里声明）。

### 阶段 4：提词页改造

9. 改 `lib/pages/teleprompter_page.dart`：
   - 变成"台词库列表 + 新建台词"（布局参考绿幕助手：顶部"新建台词"入口，下面是草稿列表）
   - 每条台词右侧「**开启悬浮窗**」按钮 → 调 `OverlayService.show(lines)`
   - 保留原有智能跟读入口

### 阶段 5：自测

10. 跑 `flutter analyze` 确认无 error。
11. 自检清单见第六节。

## 四、参照竞品（绿幕助手）的交互

- 提词器页 = **台词库**（写稿/存草稿，不是念词的地方）
- 每条草稿一个入口 → 开启悬浮窗 → 主播去抖音开播，词浮在抖音上
- 台词内容支持"说一遍自动转文字"（我们已有 ASR，可选做，非必须）

## 五、接口与数据结构（按这个实现）

```dart
// lib/services/overlay_service.dart
class OverlayService {
  static final OverlayService instance;

  Future<bool> hasPermission();        // 是否有悬浮窗权限
  Future<bool> requestPermission();    // 请求权限（跳系统设置）
  Future<bool> show(List<String> lines);   // 显示悬浮窗（台词按行拆分）
  Future<void> updateLine(int index);      // 更新当前行（0-based，-1=未开始）
  Future<void> updateLines(List<String> lines); // 换一套话术
  Future<void> hide();                 // 关闭悬浮窗
  bool get isShowing;
}
```

```dart
class Script {
  final String id;
  final String title;      // 如"零食专场"
  final String content;    // 全文，按 \n 拆行传给悬浮窗
  final DateTime updatedAt;
}
```

## 六、验收标准

- [ ] 主播在抖音直播时，台词悬浮窗浮在抖音之上
- [ ] 摄像头直播下观众**看不到**悬浮窗（安全，不穿帮）
- [ ] 台词能自动滚动 / 或跟着主播念的进度高亮当前行（智能跟读）
- [ ] 能存多套话术，开播前直接调出来用
- [ ] 悬浮窗可拖动、可调透明度
- [ ] `flutter analyze` 无 error

## 七、约束（重要）

1. **不要 `flutter build`**（构建环境今天崩了一天，Gradle 文件锁问题）。只跑 `flutter analyze`，最后由我统一构建装机。
2. 需要新依赖就改 `pubspec.yaml` 并跑 `flutter pub get`（pub get 可以）。
3. **数字人直播不用悬浮窗**（它走口型视频/AI 直接念，画面推给观众，悬浮窗会穿帮）——别给数字人加这个。
4. iOS 不支持悬浮窗，本次不做。
